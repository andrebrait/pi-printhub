# REST API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Programs use `/api` with API tokens (read or full access); the API is described by OpenAPI and shown on a Swagger UI page.

**Architecture:** A token store beside `settings.json`; the existing `Guard` middleware (which runs before any body is parsed) recognises `Authorization: Bearer`, skips the Origin check for valid tokens and enforces access by method and path; the session dependency also accepts a token the Guard validated. FastAPI generates the OpenAPI document once routes carry tags and models; Swagger UI is vendored and started by our own script.

**Tech Stack:** Python 3.13 (FastAPI, pydantic, hashlib, hmac, secrets), vanilla ES modules, Bootstrap 5.3.8, swagger-ui-dist 5.34.1.

**Spec:** `docs/superpowers/specs/2026-10-31-rest-api-design.md`

## Global Constraints

- Token format `ph_` + `secrets.token_urlsafe(32)`; stored as SHA-256 hex only, compared with `hmac.compare_digest`; never logged, never in events, never returned after creation.
- `/var/lib/printhub/api-tokens.json` (`cfg.data_dir / "api-tokens.json"`), mode 0600, written with `printhub.settings.write_json`.
- Access: `read` = every `GET` under `/api/` except `/api/tokens`; `full` = also `POST/PUT/PATCH/DELETE`; browser session only = `POST /api/login`, `POST /api/logout`, `POST /api/settings/password`, everything under `/api/tokens`.
- Errors: invalid/revoked token 401 `{"error": "Invalid API token"}` (also when a session cookie is present); read-only on a write 403 `{"error": "This API token is read-only"}`; browser-only route with a token 403 `{"error": "Not allowed with an API token"}`; 5 failed token attempts per client address per minute, then 429 `{"error": "Too many attempts; wait a minute"}` (checked before verifying).
- `last_used` written at most once a minute per token.
- No new Python or apt dependencies. Swagger UI vendored unmodified (integrity: verify `npm view swagger-ui-dist@5.34.1 dist.integrity` against the tarball), not precached.
- Tests never check source text. Commands: `docker run --rm -v $PWD:/src -w /src printhub-dev python3 -m pytest -q -k "not slow"`, `node --test static/js/*.test.js`.

## Review Focus

1. **A token sent to a route added later without a decision** — must be refused, not silently allowed. The route-classification test (Task 2) fails when a new `/api` route appears.
2. **A valid session cookie plus a wrong `Authorization` header** — must be 401, never fall back to the cookie. Task 2.
3. **A script polling `/api/status` every 2 s with a token** — must not rewrite `api-tokens.json` each time. Task 1.
4. **Upload with a read-only token** (`POST /api/uploads`, multipart) — refused before the body is read. Task 2.
5. **Swagger UI "Try it out" in the browser without a token** — works through the session (Origin header sent by the browser). Task 5, on the Pi.

### Task 1: Token store

**Files:** Create `printhub/tokens.py`; modify `printhub/auth.py`; test `tests/test_tokens.py`.

**Produces:**
- `tokens.create(data_dir: Path, name: str, access: str, now: datetime) -> tuple[dict, str]` — returns the public record `{id, name, access, created, last_used}` and the token string; validates name (stripped, 1–60) and access (`read`|`full`) with `ValueError`.
- `tokens.list_public(data_dir) -> list[dict]`, `tokens.revoke(data_dir, token_id) -> bool`.
- `tokens.verify(data_dir, presented: str, now: datetime) -> dict | None` — public record of the matching token or None; updates `last_used` only when it is older than 60 s.
- An unreadable or corrupt file: `verify` returns None and logs an error; writes refuse (raise) rather than overwrite, like `notifications.json`.
- `LoginLimiter.blocked(key: str, now: float) -> bool` (prunes, true when at the limit) without recording a hit.

- [ ] **Step 1: Failing tests:** token format and once-only return; only the hash in the file, mode 0600; verify valid/revoked/wrong; constant-time compare used via behaviour (wrong token of equal length rejected); `last_used` throttling with a fake clock (Review Focus 3); corrupt file → verify None and create refuses without overwriting; `blocked` does not count.
- [ ] **Step 2:** Run; expect failures.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run; expect pass.
- [ ] **Step 5:** Commit `feat(api): token store`.

### Task 2: Token authentication and access rules

**Files:** Modify `printhub/middleware.py`, `printhub/auth.py`, `printhub/app.py`; test `tests/test_api_tokens.py`.

**Consumes:** Task 1. **Produces:**
- `Guard` checks `Authorization` before the Origin check: `Bearer <token>` → `blocked` → 429; `verify` → None → record a hit, 401; else put the record in `scope["printhub.token"]`, skip the Origin and session checks, then apply the access rules (Global Constraints) by method and path, before any body byte is read. Any other `Authorization` scheme → 401.
- `require_session` accepts a request whose scope has a validated token.
- Routes `GET/POST /api/tokens`, `DELETE /api/tokens/{id}` (session only), with `settings` events "API token <name> created (read-only|full access)" / "API token <name> revoked".
- A module-level classification used by the Guard: `BROWSER_ONLY` (exact method+path patterns). Everything else under `/api/` is by method.

- [ ] **Step 1: Failing tests:** status with a token and no Origin → 200; invalid token + valid cookie → 401 (Review Focus 2); revoked → 401; 6th bad token in a minute → 429 and a 7th with a *valid* token from the same address is also 429; read token on every non-GET route → 403, on every GET route (except tokens) → not 401/403; read token on `POST /api/uploads` with a large multipart body is refused before the body is consumed (Review Focus 4; assert via a receive counter like the existing body-limit tests); browser-only routes refuse full tokens; session behaviour unchanged (existing tests); a test that walks `app.routes` and fails when an `/api` route is neither GET, a write, nor in `BROWSER_ONLY` (Review Focus 1); token create/list/revoke through the API, token shown once, events without the token.

### Task 3: OpenAPI document

**Files:** Modify `printhub/app.py` (and request/response models where they live); test `tests/test_openapi.py`.

**Produces:** `GET /api/openapi.json` behind the same auth (FastAPI `openapi_url` stays None; serve `app.openapi()` from an `/api` route excluded from the schema).
